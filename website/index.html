Every effect is an ISF shader. Up to 4 on every clip and 4 on the whole output, each with its own mix (alpha, luma key, inverted luma key, add) and RGB channels. Drop a .fs file into a finder folder and it's there; change it and it reloads while it plays.

What is ISF?

The Interactive Shader Format is an open standard from VIDVOX, the makers of VDMX: a normal GLSL fragment shader with a small JSON header that says which controls it has. videoping reads that header and builds the controls for you — no plugin, no compiling, the file stays as it is.

/*{
  "INPUTS": [
    { "NAME": "inputImage", "TYPE": "image" },
    { "NAME": "amount", "LABEL": "Amount",
      "TYPE": "float", "MIN": 0, "MAX": 1, "DEFAULT": 0.5 },
    { "NAME": "mono", "LABEL": "Mono", "TYPE": "bool" },
    { "NAME": "tint", "LABEL": "Tint", "TYPE": "color" }
  ]
}*/
void main() {
  vec4 c = IMG_THIS_PIXEL(inputImage);
  vec3 inv = mix(c.rgb, 1.0 - c.rgb, amount);
  if (mono) inv = vec3(dot(inv, vec3(0.33)));
  gl_FragColor = vec4(inv * tint.rgb, c.a);
}

It has an inputImage, so it's an effect; without one it would be a generator. Each control can move by itself, sit on a MIDI knob or be set by the AI.

Generator or effect?

Decided by the shader itself: an image input named inputImage makes it an effect. Where the file lies doesn't matter.

Inputs become controls

float → range slider with animation · bool → checkbox · color → color picker · long with labels → menu · point2D → x / y sliders · event → button.

Serious shaders welcome

Multi-pass, persistent buffers for feedback, custom vertex shaders, hot reload — and a .md file next to a shader shows up as its documentation.

A big world of shaders

ISF is used in VDMX and other VJ tools; a public library of shaders lives at editor.isf.video. Most run in videoping as they are.

controllers

Built around your hands, not your mouse.

The mouse is for preparing. Playing happens on hardware — instantly: MIDI is read on its own thread and applied at the next video frame.

  • 8×8 pad grid (Bhoreal profile built in): pages of clips, layer select, effects on/off, blackout and REC — every LED shows the real state, in colour.
  • 16 encoders (Midi Fighter Twister profile built in): layer mixes and master on one column, the other 12 control the effect you just opened. Push = back to default.
  • Any controller: press learn, move a knob, done. Profiles are saved per device and come back when you plug it in.
  • One press calibration: a pad grid that rotated itself? Press the pad next to the cable.

prepare & play

Tweak in peace. The audience only sees what you send.

  • Prepare lane: 32 slots a page, each with its own effects (up to 4) and settings. Select one and tune it while the mix keeps running.
  • Every parameter moves: each slider is a range with loop, bounce, jumpcut, free speed or synced to the bpm. Right click = back to default.
  • Three layers with alpha, luma key, inverted luma key and add, RGB channel switches, master brightness, blackout and freeze.
  • Shader docs inline: hover a parameter to read what it does, open the full documentation next to the effect.
ai

An assistant that knows your set — and keeps its hands where you can see them.

The ai tab talks to Claude or to a model on your own machine (Ollama, LM Studio). It uses the same controls as your MIDI controller, sees the output as an image, and shows every single change.

  • Acts, then says what it did — one line, every tool call listed with its result.
  • Undo next to each change; the assistant is told.
  • Ask before changes for shows: nothing happens until you press apply.
  • Your choice of model: Claude, OpenAI, or local and free with Ollama.
  • MCP built in: Claude Code and other assistants can drive videoping from outside — read only, if you like.
  • Your key, your machine: stored locally, readable only by you.
shader editor

Write a shader between two tracks.

A full ISF editor with a live preview: a generator on its own, an effect on the clip you selected. The file only changes when you save — the show keeps the working version until then.

  • Live while you type: compiled a quarter second after the last key.
  • Errors on the right line — of your file, not of some generated code. Click to jump.
  • Sliders right there: try the new parameters while you write them.
“add a hue shift slider and make it pulse with the bpm”

The AI reads the shader, writes the new version, sees line 159: 'colr' undeclared, fixes it, looks at the preview — and leaves saving to you. Every step has undo.
projection mapping

Boxes, stages, odd angles. Mapped in minutes.

  • Slices: any part of the composition onto any four corners, with correct perspective.
  • Masks: black out the DJ booth or a door, with soft edges — or keep only the inside.
  • Test grid on the projector while you drag; arrow keys for the last pixel.
  • Presets per venue, saved by themselves. NDI and recording stay clean — or mapped, your call.
videopong.net, built in

A whole footage library in your finder.

videopong.net is the non-profit, ad-free share-and-remix platform for VJs: more than 27,000 clips under Creative Commons licenses, made by VJs for VJs. In videoping it is simply a category of the finder.

  • Search or go random — 50 results at a time, with thumbnails, author and license.
  • Click to preview, double click into the grid, drag onto a slot.
  • Yours to keep: downloads land in a normal folder and play offline, in every future set.
  • Credit where it's due: author and license are always shown.

Completely vibecoded with Claude.

Not a single line of videoping was typed by hand. All of it — the code, the self-tests, the manual, even this page — was written by Claude, Anthropic's AI, in Claude Code. The maker of videopong.net directed it: what to build, how it has to feel on stage, and what was wrong.

A VJ describes

“the Twister should control the effect I just opened”, “the corner is hard to catch”, “clear the controller when it quits” — in plain words, from real use.

Claude builds and tests

It writes the Rust, then proves it: unit tests, and self-tests that drive the real program — simulated mouse clicks and keys, virtual MIDI controllers, mock AI servers, pixel checks of the output.

Every decision is written down

The spec (features.md), the end-user manual and the developer notes grow with every change, so nothing lives only in a chat.

Early alpha — what that means

  • It is young: expect rough edges, missing pieces and things that change.
  • Tested on very few machines so far (Pop!_OS 24.04 on Intel Iris Xe and NVIDIA). Your setup may find new bugs — please report them.
  • No packages yet: you build it from source.
  • Sessions, profiles and presets are plain JSON; their format may still change between versions. Keep backups of what matters.
